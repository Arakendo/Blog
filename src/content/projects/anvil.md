## What it is

Anvil is a desktop planning and engineering environment built around embedded tools, project data, Kanban workflows, documents, diagrams, operational utilities, and an evolving synchronization service.

## Why it matters here

Anvil is useful precisely because it is not a clean-room expression of a finished methodology. It has product history, accumulated design decisions, practical UI constraints, migrations, integrations, and recovery concerns.

## Questions it explores

- Which workflow meanings belong to roles rather than presentation labels?
- When should editing permit temporary invalidity?
- How can a host own tools without absorbing their semantics?
- What does convergence evidence look like in a local-first product?
- How should old decisions remain visible as the architecture changes?
